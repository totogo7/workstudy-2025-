借阅图书副本的信息表：

### 索引设计（汇总）

聚簇索引（主键）、唯一索引（值唯一）
复合索引

	- （book_id,copy_status）：借书的时候，查询`WHERE book_id = ? AND copy_status = 1 LIMIT 1` 定位到可借的副本
	- （user_id,satus）：查询某用户借阅历史。个人查看自己借阅记录

覆盖索引：覆盖索引指索引包含了查询需要的所有列，MySQL 可以只读索引无需回表，从而减少 IO，速度快。典型做法是将常查询的少量列放入复合索引中实现覆盖。

全文索引（FULLTEXT，查询 MATCH）

- `FULLTEXT(ft_title_author_summary)`：用于全文搜索（MySQL FULLTEXT）。注意：中文分词不佳，长期建议 ES。
- `idx_copy_book_status (book_id, copy_status)`：借书时常做 `WHERE book_id = ? AND copy_status = 1 LIMIT 1`，这个复合索引可覆盖查询并使用索引顺序。
- `idx_br_user_status (user_id, status)`：用户查看未归还、历史记录时按 user_id + status 查。
- `idx_books_isbn`：ISBN 精确查找。
- 覆盖索引（Covering Index）：在一些高频读场景，选择少量列创建复合索引以避免回表（例如查询列表只需 id,title,author，可以用索引扫描）。
- 索引顺序原则：最常被 filter 的列放在最前；用于排序的列也要考虑（如果 ORDER BY 可以走索引）。

### 并发/锁与事务（借书场景详解）

**目标**：在并发环境下，确保同一副本不会被两个用户同时借走；防止超借

1）悲观锁，事务，行锁：行加行级排他锁，防止其它事务同时拿到同一副本。

```SQL
START TRANSACTION;

-- 1) 找到一个可用副本并锁住该行（行级锁）
SELECT id FROM book_copies
 WHERE book_id = ? AND copy_status = 1
 ORDER BY id ASC
 LIMIT 1
 FOR UPDATE;

-- 若没有返回行 -> 没有可借副本，ROLLBACK并返回失败

-- 2) 标记副本为 borrowed
UPDATE book_copies SET copy_status = 2 WHERE id = <copy_id>;

-- 3) 插入 borrow_records
INSERT INTO borrow_records(user_id, copy_id, book_id, borrow_time, due_time, status)
 VALUES(...);

-- 4) 更新 books.available_copies = available_copies - 1
UPDATE books SET available_copies = available_copies - 1 WHERE id = ?;

COMMIT;

```

2）乐观锁方案（可选，高并发下减少锁开销）

- 给 `book_copies` 或 `books` 增 `version` 列（INT）。借书时：读取版本 v；UPDATE ... SET available_copies = available_copies -1, version = version+1 WHERE id = ? AND version = v；如果受影响行数 = 0，说明冲突，重试/告知失败。
- 优点：不加持久锁，适合冲突低场景；缺点：需处理重试和补偿。



## MyBatis

mybatis在图书管理项目中是负责把SQL映射到java对象。我们用它来写可控、可优化的sql。比JDBC少得多的样例代码。

在结构上 controller -- service -- mapper（mybatis）--db

把sql（写在xml或注解）映射成java方法，返回实体

**1) Mapper 接口 + XML（核心）**

```
@Mapper
public interface BookCopyMapper {
  Long selectAvailableCopyForUpdate(@Param("bookId") Long bookId);
  int updateCopyStatus(@Param("id") Long id, @Param("status") int status);
}
```

XML（`mapper/BookCopyMapper.xml`）：

```
<select id="selectAvailableCopyForUpdate" resultType="long" parameterType="long">
  SELECT id FROM book_copies
  WHERE book_id = #{bookId} AND copy_status = 1
  ORDER BY id ASC
  LIMIT 1
  FOR UPDATE
</select>
```

**说明**：`FOR UPDATE` 在事务内会加行级锁，保证并发安全；这是 MyBatis 把 SQL 能力直接暴露出来的好处。

**2) Service 层使用 Mapper（事务注解）**

```
@Service
public class BorrowServiceImpl implements BorrowService {
  @Resource
  private BookCopyMapper bookCopyMapper;

  @Transactional
  public Long borrowBook(Long userId, Long bookId) {
    Long copyId = bookCopyMapper.selectAvailableCopyForUpdate(bookId);
    if (copyId == null) throw new RuntimeException("no available copy");
    bookCopyMapper.updateCopyStatus(copyId, 2);
    // insert record, update books.availableCopies...
    return recordId;
  }
}
```

**说明**：Mapper 专注 SQL，Service 管理事务与业务流程（组合多个 mapper 操作），职责清晰。

把请求链路分层说明，面试说清楚每层职责与 MyBatis 的位置：

```
Controller (接收 HTTP 请求) 
  → Service (业务逻辑、事务边界 @Transactional)
    → MyBatis Mapper (SQL 层，XML/注解写 SQL)
      → JDBC (由 MyBatis 管理 Connection/PreparedStatement)
        → MySQL (数据库)
```

同时补充其他模块如何参与：

- **Config**：`DataSource`（HikariCP）、`@MapperScan`、MyBatis 配置（typeAliases、mapperLocations）。
- **Flyway**：做 schema migration（DB 表结构由 Flyway 管理，与 MyBatis 配合）。
- **事务管理**：由 Spring 的 `DataSourceTransactionManager` 管理，`@Transactional` 在 Service 层控制事务边界。
- **测试**：Testcontainers 启 DB，SpringBootTest + `@MapperScan` 自动装配 Mapper，执行集成测试。

一句话总结：MyBatis 是连接 Service 与 MySQL 的桥梁，负责执行 SQL 与把结果映射回 Java，对外只暴露接口方法给 Service 使用。

# 

1. **Q：MyBatis 是如何防止 SQL 注入的？**
    A（示例答）：使用 `#{}`（PreparedStatement 占位）会自动用参数绑定从而防止注入；`$ {}` 是字符串拼接，不安全，只有在拼接列名/排序字段时谨慎使用并做白名单校验。
2. **Q：你们怎么做分页？**
    A：我们用 PageHelper 或自己用 `LIMIT #{offset}, #{limit}`。对于大页号改用 Keyset pagination（`WHERE id > lastId LIMIT n`）以避免 offset 性能问题。
3. **Q：Mapper 的 XML 与注解哪个更好？**
    A：XML 适合复杂 SQL 和维护（分离层次）；注解适合简单 SQL。我们用 XML 来管理复杂的查询（比如 search、FOR UPDATE、JOIN），注解用于很短的 CRUD。
4. **Q：如何做动态 SQL？**
    A：使用 MyBatis 的 `<if>`, `<choose>`, `<foreach>` 在 XML 中生成条件和 IN 列表，方便又清晰。例如搜索筛选、批量 insert/更新会用 `<foreach>`。
5. **Q：MyBatis 的一级/二级缓存是怎样的？**
    A：一级缓存基于 SqlSession（同一次 session 内可复用），默认开启；二级缓存是 mapper 级别的（需显式开启并配置缓存实现），适用于读多写少场景。生产中要慎用二级缓存，注意事务一致性与缓存失效策略。
6. **Q：如何处理大事务或死锁？**
    A：在 Service 层控制事务粒度，保持事务尽可能短；捕获死锁异常（如 `ER_LOCK_DEADLOCK`），做指数退避重试；优化 SQL 和索引以减少锁争用。
7. **Q：为什么不直接用 JPA/Hibernate？**
    A（简短）：JPA 自动化方便，但对复杂查询/性能调优不够透明。我们需要精确控制 SQL（`FOR UPDATE`、复杂聚合、手写优化），所以选 MyBatis。
8. **Q：如何单元测试 Mapper？**
    A：Mapper 可以在 SpringBootTest 环境下与 Testcontainers 的 MySQL 做集成测试；单元层可以 mock Mapper（Mockito）测试 Service 逻辑。
9. **Q：Mapper XML 的 resultMap 有什么用？**
    A：当列名和属性名不一致或有复杂关联（one-to-many、nested result）时，用 resultMap 指定精确映射，避免类型/列名映射错误。
10. **Q：如何处理 ENUM/特殊类型映射？**
     A：用 MyBatis 的 TypeHandler（自定义）处理枚举与 DB 字段转换，或用 MyBatis 的 `typeHandlersPackage` 全局配置。

# 

- **“在高并发下 MyBatis 与 Redis 结合的模式是什么？”**
   答：常见是 Redis 预减库存（atomic DECR），若成功再请求 DB 写入并用消息队列最终一致性补偿；复杂逻辑用 SQL 行锁（悲观锁）在 DB 层做强一致，Redis 做读缓存/热点保护。可根据并发量和一致性需求权衡。
- **“如何在 MyBatis 中做批量插入/更新？”**
   答：用 `<foreach>` 生成批量 `INSERT`，并设置 `useGeneratedKeys` 或返回主键。也可借助 MyBatis-Plus 或 MyBatis Generator。
- **“如何监控 SQL 执行？”**
   答：在项目中启用慢查询日志、使用 p6spy 或 datasource proxy 打印 SQL（带参数），并结合 APM（SkyWalking）和 Prometheus/Grafana 监控 DB 指标。



“选 MyBatis 是因为我们既要**掌控 SQL 性能与并发行为**（比如借书的 `FOR UPDATE`），又要**减少原生 JDBC 的样板代码**，在项目里它通过 Mapper 把 SQL 映射为方法，Service 层注入这些 Mapper 并在 `@Transactional` 边界内组合调用，形成 Controller→Service→Mapper→DB 的清晰链路，这样既满足可维护性又满足性能调优能力。”

##### 3A) 实现一 — 手写 `LIMIT` + `COUNT`（放 `service/impl/BookServiceImpl.java`）

> 适合你已经有 mapper 的场景，最明确、最可控。

```java
package org.example.library.service.impl;

import org.example.library.dto.PageResult;
import org.example.library.entity.Book;
import org.example.library.mapper.BookMapper;
import org.example.library.service.BookService;
import org.springframework.stereotype.Service;
import jakarta.annotation.Resource;

import java.util.Collections;
import java.util.List;

@Service
public class BookServiceImpl implements BookService {

    @Resource
    private BookMapper bookMapper;

    @Override
    public PageResult<Book> searchBooks(String q, int page, int size) {
        if (page < 1) page = 1;
        if (size <= 0) size = 10;
        int offset = (page - 1) * size;

        // 防止 null 导致 mapper SQL 问题
        String keyword = (q == null) ? "" : q.trim();

        List<Book> list = Collections.emptyList();
        long total = 0;
        // 当关键字为空且不想走 count 或特殊处理时可以优化，这里直接统一走两条查询
        list = bookMapper.search(keyword, offset, size);
        total = bookMapper.countSearch(keyword);

        return new PageResult<>(list, total, page, size);
    }

    @Override
    public PageResult<Book> searchBooksByCursor(String q, Long lastId, int size) {
        // 见下面 Keyset 实现示例
        if (size <= 0) size = 10;
        String keyword = (q == null) ? "" : q.trim();

        List<Book> list;
        if (lastId == null || lastId <= 0) {
            // 首页：无 lastId，直接取最新的 size 条
            list = bookMapper.searchByKeysetFirstPage(keyword, size);
        } else {
            list = bookMapper.searchByKeysetAfterId(keyword, lastId, size);
        }
        // Keyset 不返回总数，设 total = -1 或返回估算
        return new PageResult<>(list, -1, 0, size);
    }
}
```

> 说明：
>
> - `bookMapper.search(keyword, offset, size)` 和 `countSearch` 为你现有方法。
> - `searchBooksByCursor` 调用的是你要额外实现的 Keyset mapper（示例在下文）。
> - 这个实现把分页逻辑放在 Service，便于单元测试与复用。

##### 3B) 实现二 — 使用 PageHelper（放 `service/impl/BookServicePageHelperImpl.java`）

> 如果你引入 PageHelper 插件，Service 更简洁。先在 `pom.xml` 加依赖（我之前给过），然后：

```java
package org.example.library.service.impl;

import com.github.pagehelper.PageHelper;
import com.github.pagehelper.PageInfo;

import org.example.library.entity.Book;

import java.util.List;

@Service
public class BookServicePageHelperImpl implements BookService {

    @Resource
    private BookMapper bookMapper;

    @Override
    public PageResult<Book> searchBooks(String q, int page, int size) {
        if (page < 1) page = 1;
        if (size <= 0) size = 10;
        String keyword = (q == null) ? "" : q.trim();

        PageHelper.startPage(page, size);
        // 这里 mapper.search 参数可调整：若 mapper 定义了 offset/limit 参数，可忽略或传 0
        List<Book> list = bookMapper.search(keyword, 0, 0);
        PageInfo<Book> pageInfo = new PageInfo<>(list);

        return new PageResult<>(pageInfo.getList(), pageInfo.getTotal(), pageInfo.getPageNum(), pageInfo.getPageSize());
    }

    @Override
    public PageResult<Book> searchBooksByCursor(String q, Long lastId, int size) {
        // 同上 Keyset 处理
        if (size <= 0) size = 10;
        String keyword = (q == null) ? "" : q.trim();
        List<Book> list;
        if (lastId == null || lastId <= 0) {
            list = bookMapper.searchByKeysetFirstPage(keyword, size);
        } else {
            list = bookMapper.searchByKeysetAfterId(keyword, lastId, size);
        }
        return new PageResult<>(list, -1, 0, size);
    }
}
```

> 说明：PageHelper 会拦截 Mapper 的查询并自动注入 `LIMIT`，并自动执行 `COUNT` 获取 total（默认行为）。PageHelper 常见于企业项目，省事省代码。

5) Keyset（游标）分页：Mapper 示例 SQL（把这两条加到你的 BookMapper.xml）

```xml
<!-- 首页：取最新的 N 条 -->
<select id="searchByKeysetFirstPage" resultMap="BookMap">
  SELECT id, isbn, title, author, available_copies
  FROM books
  WHERE (title LIKE CONCAT('%', #{q}, '%') OR author LIKE CONCAT('%', #{q}, '%') OR isbn LIKE CONCAT('%', #{q}, '%'))
  ORDER BY id DESC
  LIMIT #{size}
</select>

<!-- 翻页：取 id < lastId 的下一页 -->
<select id="searchByKeysetAfterId" resultMap="BookMap">
  SELECT id, isbn, title, author, available_copies
  FROM books
  WHERE (title LIKE CONCAT('%', #{q}, '%') OR author LIKE CONCAT('%', #{q}, '%') OR isbn LIKE CONCAT('%', #{q}, '%'))
    AND id < #{lastId}
  ORDER BY id DESC
  LIMIT #{size}
</select>
```

> 注意：Keyset 在 `ORDER BY id DESC` 且 `id` 为自增主键时最稳定；若你按其他列排序，Keyset 要用复合条件并确保排序列上有索引。

## Redis缓存

Redis 用来缓解数据库读压力、加速热点数据访问（比如图书详情页、热门榜），并能做简单的计数/排名（ZSET）来实现热度排行榜 —— 对比直接读 MySQL，Redis 的响应更快（内存）、并支持原子操作。

> 下面用 `RedisTemplate<String, String>` + Jackson 将对象序列化为 JSON 存储。也展示用 Redis 的 ZSET 维护热度。

​```java
package org.example.library.service.impl;

import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.ObjectMapper;
import jakarta.annotation.Resource;
import org.example.library.entity.Book;
import org.example.library.mapper.BookMapper;
import org.example.library.service.BookCacheService;
import org.springframework.data.redis.core.*;
import org.springframework.stereotype.Service;

import java.time.Duration;
import java.util.*;
import java.util.stream.Collectors;

// 标记为Spring服务类，用于实现图书缓存相关业务逻辑
@Service
public class BookCacheServiceImpl implements BookCacheService {

    // 缓存键前缀：图书详情缓存的键前缀，格式为"book:detail:图书ID"
    private static final String KEY_BOOK = "book:detail:";
    // 缓存键：热门图书排序集合的键，用于存储图书热度评分
    private static final String KEY_HOT = "book:hot";
    // 缓存键前缀：空值占位符的键前缀，用于防止缓存穿透
    private static final String KEY_PLACEHOLDER = "placeholder:book:";

    // 注入RedisTemplate，用于操作Redis缓存
    @Resource
    private RedisTemplate<String, String> redisTemplate;
    // 注入ObjectMapper，用于JSON序列化和反序列化
    @Resource
    private ObjectMapper objectMapper;
    // 注入BookMapper，用于从数据库查询图书信息（缓存旁路模式中使用）
    @Resource
    private BookMapper bookMapper; // 直接访问mapper用于cache-aside模式

    /**
     * 从缓存中获取图书信息
     * @param bookId 图书ID
     * @return 缓存中的图书对象，若缓存不存在或为占位符则返回null
     */
    @Override
    public Book getBookFromCache(Long bookId) {
        // 构建缓存键：前缀 + 图书ID
        String key = KEY_BOOK + bookId;
        // 从Redis中获取对应的值（JSON字符串）
        String json = redisTemplate.opsForValue().get(key);
        // 缓存不存在，直接返回null
        if (json == null) return null;
        // 处理空值占位符：如果缓存值是__NULL__，表示数据库中也不存在该图书，返回null
        if ("__NULL__".equals(json)) return null;
        // 将JSON字符串反序列化为Book对象并返回
        try {
            return objectMapper.readValue(json, Book.class);
        } catch (Exception e) {
            // 反序列化失败时抛出运行时异常
            throw new RuntimeException(e);
        }
    }

    /**
     * 使用缓存旁路模式（Cache-Aside）获取图书信息
     * 逻辑：先查缓存，命中则返回；未命中则查数据库，再将结果写入缓存
     * @param bookId 图书ID
     * @return 图书对象（来自缓存或数据库）
     */
    @Override
    public Book getBookWithCacheAside(Long bookId) {
        // 构建缓存键
        String key = KEY_BOOK + bookId;
        // 从缓存获取数据
        String cached = redisTemplate.opsForValue().get(key);
        // 缓存命中
        if (cached != null) {
            // 若为占位符，返回null
            if ("__NULL__".equals(cached)) return null;
            // 反序列化为Book对象并返回
            try { return objectMapper.readValue(cached, Book.class); }
            catch (Exception e) { throw new RuntimeException(e); }
        }

        // 缓存未命中，从数据库查询
        Book b = bookMapper.findById(bookId);
        // 数据库中也不存在该图书
        if (b == null) {
            // 设置空值占位符到缓存（短期过期），防止缓存穿透（大量无效请求直击数据库）
            redisTemplate.opsForValue().set(KEY_PLACEHOLDER + bookId, "__NULL__", Duration.ofSeconds(60));
            // 同时在图书详情缓存键下也设置占位符，保持一致性
            redisTemplate.opsForValue().set(key, "__NULL__", Duration.ofSeconds(60));
            return null;
        }

        // 数据库查询成功，将结果写入缓存
        try {
            // 将Book对象序列化为JSON字符串
            String json = objectMapper.writeValueAsString(b);
            // 设置缓存过期时间（10~15分钟随机），避免缓存雪崩（大量缓存同时过期）
            long ttl = 60 * 10 + new Random().nextInt(60 * 5); // 10分钟基础上增加0~5分钟随机值
            redisTemplate.opsForValue().set(key, json, Duration.ofSeconds(ttl));
        } catch (Exception e) { 
            // 序列化或写入缓存失败时可在此处记录日志，不抛出异常避免影响主流程
        }
        // 返回数据库查询到的图书对象
        return b;
    }

    /**
     * 清除指定图书的缓存
     * 通常在图书数据更新后调用，保证缓存与数据库一致性
     * @param bookId 图书ID
     */
    @Override
    public void evictBookCache(Long bookId) {
        // 删除图书详情缓存
        redisTemplate.delete(KEY_BOOK + bookId);
        // 删除对应的空值占位符缓存
        redisTemplate.delete(KEY_PLACEHOLDER + bookId);
    }

    /**
     * 将图书信息存入缓存，并指定过期时间
     * @param bookId 图书ID
     * @param book 图书对象
     * @param ttlSeconds 过期时间（秒）
     */
    @Override
    public void putBookCache(Long bookId, Book book, long ttlSeconds) {
        try {
            // 将图书对象序列化为JSON字符串
            String json = objectMapper.writeValueAsString(book);
            // 写入缓存并设置过期时间
            redisTemplate.opsForValue().set(KEY_BOOK + bookId, json, Duration.ofSeconds(ttlSeconds));
        } catch (Exception e) {
            // 异常时记录日志，不影响主流程
        }
    }

    /**
     * 获取热门图书列表（按热度排序的前N名）
     * @param topN 要获取的数量
     * @return 热门图书列表
     */
    @Override
    public List<Book> getHotBooks(int topN) {
        // 获取Redis的ZSet操作对象（用于操作有序集合）
        ZSetOperations<String, String> z = redisTemplate.opsForZSet();
        // 从热门图书有序集合中获取分数从高到低的前N个图书ID（reverseRange表示倒序）
        Set<String> ids = z.reverseRange(KEY_HOT, 0, topN - 1);
        // 若没有数据，返回空列表
        if (ids == null || ids.isEmpty()) return Collections.emptyList();
        
        // 批量构建图书详情缓存的键（前缀+图书ID）
        List<String> keys = ids.stream().map(id -> KEY_BOOK + id).collect(Collectors.toList());
        // 批量查询缓存中的图书详情JSON（使用multiGet实现 pipeline 效果，减少网络交互）
        List<String> jsons = redisTemplate.opsForValue().multiGet(keys);
        
        // 解析JSON为Book对象并收集结果
        List<Book> res = new ArrayList<>();
        for (String j : jsons) {
            // 跳过空值或占位符
            if (j == null || "__NULL__".equals(j)) continue;
            try {
                res.add(objectMapper.readValue(j, Book.class));
            } catch (Exception e) {
                // 解析失败时可跳过或从数据库查询作为降级方案
            }
        }
        return res;
    }

    /**
     * 增加图书的热度评分
     * @param bookId 图书ID
     * @param delta 增加的评分值（可正可负）
     */
    @Override
    public void incrementHotScore(Long bookId, double delta) {
        // 操作有序集合，为指定图书ID的分数增加delta值
        redisTemplate.opsForZSet().incrementScore(KEY_HOT, String.valueOf(bookId), delta);
    }
}

### 4) 借书流程中对缓存的处理（BorrowServiceImpl 改动）

在借书成功后，**两种做法**推荐其一：

- **方案 A（简单且安全）**：DB 更新后 `evictBookCache(bookId)`。下次请求会回填缓存。
- **方案 B（实时性更好）**：DB 更新成功后 **在 Redis 里原子更新 cached Book 的 `availableCopies`**，减少回源。需要用 Lua 脚本或读写 JSON 并写会更复杂。

示例采用方案 A（先实现）：

```java
// 在 borrowBook 方法最后：
bookMapper.update(book); // 已做
bookCacheService.evictBookCache(bookId);
bookCacheService.incrementHotScore(bookId, 1.0); // 热度 +1
```

如果你想做**原子更新缓存 availableCopies**，可以在 Redis 使用 Lua 脚本读取 JSON、修改字段并写回，或将 availableCopies 单独存在 `book:available:{id}` 做原子 DECR/INCR（推荐做法）。

防止缓存问题（穿透 / 击穿 / 雪崩）与实操策略

1. **缓存穿透（请求不存在的 key）**
   - 将空结果写入缓存（`"__NULL__"`）并设置短 TTL（30–60s）。
2. **缓存击穿（热点 key 在 TTL 到期瞬间大量请求）**
   - 使用分布式互斥锁（`SET lock:book:{id} NX PX 5000`），只有拿到锁的线程去 DB 回填，其他线程等待或直接返回旧值/限流。
   - 或使用互斥式缓存重建（single-flight）：先查询缓存，若 miss 则用 SETNX 抢锁并回填。
3. **缓存雪崩（大量 key 同时失效）**
   - 随机化 TTL（例如 10min ± 0~5min），避免同一时刻大量过期。
4. **缓存穿透/恶意请求**
   - 对查询参数做白名单/校验，限制频繁无效请求（IP 限流）。

    String key = KEY_BOOK + bookId;
    // 构建分布式锁的键（针对当前图书ID的锁）

    if (Boolean.TRUE.equals(ok)) {

面试问答速成（常被问到的问题 + 精简答案）

Q：**为什么用 Cache-Aside 而不是 Write-Through？**
 A：Cache-Aside 写入复杂业务更安全（写 DB 首先成功，再失效缓存），避免写失败导致缓存和 DB 不一致。Write-Through 简单但每次写要同步写缓存与 DB，复杂事务易错。

Q：**如何保证缓存与 DB 强一致？**
 A：严格做 DB 写成功后立即删除/更新缓存，或者借助消息队列做最终一致性；但强一致往往牺牲性能，需权衡。

Q：**如何防止热点缓存失效时数据库洪峰？**
 A：采用互斥锁（single-flight）确保只有一个线程重建缓存、并使用随机 TTL 与预热减少同一时刻过期。

Q：**为什么用 ZSET 存热度？不是 DB 的 count 字段？**
 A：ZSET 原子且支持排名查询（ZREVRANGE），在大量并发场景下比不停更新 DB 的计数列更轻量。DB 可做慢周期持久化同步（定时批量落库）。

小结（你面试时可背）

1. 缓存策略用 Cache-Aside：读先查 redis → miss 去 DB → 写回 redis；写操作 DB 成功后 evict cache。
2. 缓存对象：图书详情（短中 TTL）、热门榜（ZSET）、可借副本计数可用 Redis 原子操作。
3. 防护：空值缓存、分布式锁（SET NX）、TTL 随机化、防雪崩、降级。
4. 代码要点：`RedisConfig` + `BookCacheService` 抽象缓存细节，`BookService` 只关心业务，减少耦合。
5. 监控/测试要到位——命中率、miss率、redis memory/eviction。
