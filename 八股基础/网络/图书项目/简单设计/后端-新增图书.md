## 🔑 第一步：理清框架

我们在 IDEA 里，Spring Boot 项目的 **后端代码结构** 一般如下：

```
src
 └── main
      ├── java
      │    └── com.library   # 根包
      │          ├── controller   # 控制层，处理前端请求
      │          ├── service      # 业务逻辑层
      │          ├── service.impl # 业务逻辑实现
      │          ├── mapper       # 数据库持久层（MyBatis 接口）
      │          ├── entity       # 实体类（数据库表对应的对象）
      │          ├── dto          # 数据传输对象（比如分页查询时的请求参数）
      │          └── common       # 公共类（统一返回结果、异常处理等）
      │
      └── resources
            ├── application.yml   # 配置文件
            ├── mapper            # 存放 MyBatis 的 XML 映射文件
            └── static / templates (如果有前端页面)
```

## 🔑 第二步：挑一个功能来完整开发（示例：📚 图书管理 → 新增图书）

### 1. 数据库表

`book` 表（在 MySQL 里创建）：

```sql
CREATE TABLE book (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    author VARCHAR(255),
    category VARCHAR(100),
    publish_date DATE,
    status TINYINT DEFAULT 1 COMMENT '1:可借 0:下架',
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

------

### 2. 实体类（`entity/Book.java`）

这时候`Book.java`实体类的作用就来了：它把数据库表的 “一行数据”，**映射成一个 Java 对象**

数据库表只能存 “原始数据”（比如`status=1`），但实体类可以给数据 “加业务含义”，让代码更符合实际业务。

```java
package com.library.entity;

import lombok.Data;
import java.time.LocalDate;

@Data
public class Book {
    private Long id;
    private String title;
    private String author;
    private String category;
    private LocalDate publishDate;
    private Integer status;
}
```

### 3. Mapper 层（`mapper/BookMapper.java`）

Mapper 层是 MyBatis 框架的核心组件，作用是**定义数据库操作的接口**，并将 Java 方法与 SQL 语句关联起来 

告诉 MyBatis：我要执行什么 SQL，参数是什么，返回什么结果

Mapper 层通过接口 + 注解（或 XML）的方式，让你只需要定义 “要执行什么 SQL”，剩下的数据库连接、SQL 执行、结果转换工作，全由 MyBatis 自动完成

```java
package com.library.mapper;

import com.library.entity.Book;
import org.apache.ibatis.annotations.*;

import java.util.List;

@Mapper
public interface BookMapper {

    // 插入图书  @Insert注解：声明这是一个 “插入数据” 的 SQL，括号里是具体的 INSERT 语句。
    @Insert("INSERT INTO book(title, author, category, publish_date, status) " +
            "VALUES(#{title}, #{author}, #{category}, #{publishDate}, #{status})")
    void insert(Book book);

    // 查询全部图书
    @Select("SELECT * FROM book")
    List<Book> findAll();
}
```

对应的 XML 映射文件也可以写在 `resources/mapper/BookMapper.xml`（复杂 SQL 推荐写 XML）。

```xml
<!-- BookMapper.xml -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" 
"http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<!-- namespace必须和Mapper接口的全类名一致 -->
<mapper namespace="com.library.mapper.BookMapper">

    <!-- 对应insert方法：id必须和接口方法名一致 -->
    <insert id="insert">
        INSERT INTO book(title, author, category, publish_date, status)
        VALUES(#{title}, #{author}, #{category}, #{publishDate}, #{status})
    </insert>

    <!-- 对应findAll方法 -->
    <select id="findAll" resultType="com.library.entity.Book">
        SELECT * FROM book
    </select>

    <!-- 复杂SQL示例：根据分类和状态查询图书 -->
    <select id="findByCategoryAndStatus" resultType="com.library.entity.Book">
        SELECT * FROM book
        WHERE category = #{category}
          AND status = #{status}
    </select>
</xml>
```

用了xml之后，接口就可以不用注解，只保留方法定义。

在整个后端分层架构中，Mapper 层处于 “最底层”，直接对接数据库，上层是 Service 层

------

### 4. Service 层（`service/BookService.java`）

**核心定位：业务逻辑的 “中枢”**—— 上承 `Controller` 层（接收前端请求），下接 `Mapper` 层（操作数据库）。

专门处理 “业务规则、数据校验、逻辑判断”，避免让 `Controller` 直接操作数据库，也避免让 `Mapper` 处理业务逻辑，是分层架构中 “承上启下” 的关键环节。

Service 接口（`BookService.java`）的功能：它的核心作用是**定义 “业务方法的规范 / 契约”**，告诉上层（如 `Controller`）：“Service 层能提供哪些业务功能，但具体怎么实现的，你不用管”。

```java
package com.library.service;

import com.library.entity.Book;
import java.util.List;

public interface BookService {
    void addBook(Book book);
    List<Book> listBooks();
}
```

### 5. Service 实现层（`service/impl/BookServiceImpl.java`）

`BookServiceImpl.java` 是 `BookService` 接口的**具体实现类**，核心作用是：**落地接口定义的业务方法，处理具体业务逻辑（包括调用 `Mapper` 层操作数据库）**。

1. **调用 Mapper 操作数据库**：Service 层是唯一能调用 Mapper 层的地方，通过注入 `BookMapper`，委托 Mapper 执行 SQL（如 `bookMapper.insert(book)`），自己不直接碰数据库。
2. **被 Spring 管理**：`@Service` 注解让 Spring 将其识别为 “Bean”，后续 `Controller` 层可以通过 `@Resource` 或 `@Autowired` 注入 `BookService` 接口，直接调用方法（不用自己 `new` 对象）。

```java
package com.library.service.impl;

import com.library.entity.Book;
import com.library.mapper.BookMapper;
import com.library.service.BookService;
import org.springframework.stereotype.Service;

import javax.annotation.Resource;
import java.util.List;

// @Service：告诉Spring“这是一个服务层的Bean”，让Spring自动创建并管理它（后续可注入使用）
@Service
// 实现BookService接口，必须重写接口的所有方法
public class BookServiceImpl implements BookService {
// @Resource：注入BookMapper对象（依赖注入）
// 为什么能注入？因为BookMapper加了@Mapper，Spring生成了它的代理对象，也是Spring管理的Bean
    @Resource
    private BookMapper bookMapper;

    @Override
    public void addBook(Book book) {
        bookMapper.insert(book);
    }

    @Override
    public List<Book> listBooks() {
         // 调用Mapper层的findAll方法，获取数据库中的所有图书
        return bookMapper.findAll();
    }
}
```

### 6. Controller 层（`controller/BookController.java`）

1. 接收前端请求：明确 “哪个请求该我处理”
2. 解析请求参数：把前端数据转成java能懂的格式（主要是一些注解）
3. 调用Service层
4. 返回统一结果

专门负责**接收前端发送的请求、解析请求参数、调用 Service 层处理业务、最后给前端返回统一格式的结果**。

它不直接操作数据库，也不处理复杂业务逻辑，只做 “请求进来” 和 “结果出去” 的中间衔接工作，是分层架构中 “直面前端” 的第一层。

```java
package com.library.controller;

import com.library.common.Result;
import com.library.entity.Book;
import com.library.service.BookService;
import org.springframework.web.bind.annotation.*;

import javax.annotation.Resource;
import java.util.List;

// 1. @RestController：告诉Spring“这是一个Controller，且所有方法返回JSON格式数据”
// （相当于 @Controller + @ResponseBody 的组合，适配前后端分离场景，前端需要JSON数据）
@RestController
// 2. @RequestMapping("/books")：定义当前Controller的“基础请求路径”
// 意思是：所有访问这个Controller的请求，URL都要以“/books”开头（如 /books、/books/1）
@RequestMapping("/books")
public class BookController {

    // 3. @Resource：注入BookService接口对象（依赖注入）
    // 为什么能注入？因为BookServiceImpl加了@Service，是Spring管理的Bean
     // Controller只依赖Service接口，不依赖具体实现类（解耦）
    @Resource
    private BookService bookService;

    // 新增图书
    // 1. @PostMapping：表示这个方法处理“POST类型”的HTTP请求
    // 结合类上的@RequestMapping("/books")，完整请求路径是：POST /books
    @PostMapping
    // 2. @RequestBody Book book：将前端发送的“JSON格式请求体”自动转换成Book对象
    // 例：前端发JSON {"title":"西游记","author":"吴承恩"}，Spring会自动把它转成Book对象，赋值给book参数
// 3. 返回值 Result<String>：返回统一格式的结果（Result是自定义的统一结果类）
    public Result<String> addBook(@RequestBody Book book) {
// 核心逻辑：调用Service层的addBook方法，委托Service处理“新增图书”的业务（如校验书名、调Mapper插数据库）
        bookService.addBook(book);
// 返回“成功”结果：给前端返回code（成功码）、msg（提示信息），这里data为null（新增成功不需要返回数据）
        return Result.success("添加成功！");
    }

    // 查询所有图书
    // 1. @GetMapping：表示这个方法处理“GET类型”的HTTP请求
    @GetMapping
    public Result<List<Book>> listBooks() {
        return Result.success(bookService.listBooks());
    }
}
```

### 7. 统一返回结果类（`common/Result.java`）

```java
package com.library.common;

import lombok.Data;

@Data
public class Result<T> {
    private Integer code;  // 1 success, 0 fail
    private String msg;
    private T data;

    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.setCode(1);
        r.setMsg("success");
        r.setData(data);
        return r;
    }

    public static <T> Result<T> error(String msg) {
        Result<T> r = new Result<>();
        r.setCode(0);
        r.setMsg(msg);
        return r;
    }
}
```

## 🔑 第三步：接口测试

**验证后端提供的 API（接口）是否能按照预期接收请求、执行业务逻辑、返回正确格式的结果**

结合你项目中的 “新增图书” 和 “查询所有图书” 接口，下面从**测试前准备→工具实操（Postman/IDEA HTTP Client）→前端联调测试→结果验证与问题排查**。

首先检查数据库：需要确定application.yml是否配置成功

1. 启动 Spring Boot 项目（IDEA → `LibraryApplication` 主类 → Run）。

2. 使用 **Postman** / **IDEA HTTP client** 测试接口：

   - Postman 是可视化的接口测试工具，支持所有 HTTP 请求方法，操作直观，适合新手

   - **新增图书**
      `POST http://localhost:8080/books`

     ```json
     {
       "title": "活着",
       "author": "余华",
       "category": "文学",
       "publishDate": "1993-05-01",
       "status": 1
     }
     ```

   - **查询所有图书**
      `GET http://localhost:8080/books`

   - 查看下方 “Response” 区域。若显示`200 OK`，说明请求被后端成功接收并处理（若显示 4xx/5xx，说明有错误，需排查）；

   - 验证数据是否真正插入数据库

3. 你也可以在前端页面用 Axios 请求这个接口，直接联调。

------

📌 到这里，你就完成了 **一个完整功能闭环**：前端提交表单 → Controller 接收请求 → Service 处理 → Mapper 调用数据库 → 返回前端展示。

在整个后端架构中，Controller 处于 “最上层”，直面前端，流程如下：

```plaintext
前端页面 → Controller 层（接收请求→解析参数→调 Service） → Service 层（处理业务→调 Mapper） → Mapper 层（执行 SQL→查数据库） → 数据库
```

用 “新增图书” 举个完整例子：

1. 前端操作：用户在 “新增图书” 弹窗输入书名 “西游记”、作者 “吴承恩”，点击 “保存”；
2. 前端发请求：向 `http://localhost:8080/books` 发 POST 请求，请求体是 `{"title":"西游记","author":"吴承恩"}`；
3. Controller 接收：`BookController` 的 `addBook` 方法被触发，`@RequestBody` 把 JSON 转成 Book 对象；
4. Controller 调 Service：`bookService.addBook(book)`，把 Book 对象传给 Service；
5. Service 处理：`BookServiceImpl` 的 `addBook` 方法先校验 “书名非空”，然后调用 `bookMapper.insert(book)`；
6. Mapper 操作数据库：`BookMapper` 执行 `INSERT` SQL，把数据插入 `book` 表；
7. 结果返回：数据库返回成功 → Mapper 返给 Service → Service 返给 Controller → Controller 返给前端 `{"code":1,"msg":"添加成功！","data":null}`；
8. 前端展示：收到结果后，关闭弹窗，刷新图书表格，显示 “添加成功” 提示。
