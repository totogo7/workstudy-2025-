用户登录是一个 **核心功能**，涉及到：

1. **数据库建表**
2. **后端实现（Controller + Service + Mapper）**
3. **密码加密存储（安全）**
4. **登录成功生成 Token（认证）**
5. **拦截器校验 Token（鉴权）**
6. **Redis 缓存优化（提升性能，避免频繁查库）**

我会先给出基本功能代码，然后再说优化思路。

### 实现（`service/impl/UserServiceImpl.java`）

实现登录业务逻辑，包括 “查询用户→密码加密验证→返回结果”，是登录功能的 “大脑”。

```java
package com.library.service.impl;

import com.library.entity.User;
import com.library.mapper.UserMapper;
import com.library.service.UserService;
import com.library.util.JwtUtil;
import org.springframework.stereotype.Service;
import org.springframework.util.DigestUtils;

import javax.annotation.Resource;

// 标记为服务层组件，由Spring管理
@Service
public class UserServiceImpl implements UserService {

    @Resource // 注入UserMapper，用于查询数据库
    private UserMapper userMapper;

    @Override
    public User login(String username, String password) {
         // 步骤1：根据用户名查数据库，获取用户信息
        User user = userMapper.findByUsername(username);
        if (user == null) return null; // 用户名不存在 → 登录失败

        // MD5 加密对比
        String encryptedPwd = DigestUtils.md5DigestAsHex(password.getBytes());
        if (!encryptedPwd.equals(user.getPassword())) {
            return null;
        }
        // 步骤3：验证通过，返回用户信息（用于后续生成token）
        return user;
    }
}
```

## 🔑 第五步：Controller（`controller/UserController.java`）

作为前端与后端的 “桥梁”，接收登录请求参数，调用 Service 层验证，生成 token 并返回给前端（前端后续请求需携带此 token 证明身份）。

```java
package com.library.controller;

import com.library.common.Result;
import com.library.entity.User;
import com.library.service.UserService;
import com.library.util.JwtUtil;
import org.springframework.web.bind.annotation.*;

import javax.annotation.Resource;
import java.util.HashMap;
import java.util.Map;
// 标记为REST接口控制器，返回JSON格式响应
@RestController
@RequestMapping("/user") // 基础路径：所有用户相关接口以/user开头
public class UserController {

    @Resource
    private UserService userService;

    @PostMapping("/login") // 处理POST请求：/user/login
    public Result<Map<String, String>> login(@RequestParam String username, // 接收请求参数：用户名
                                             @RequestParam String password) {  // 接收请求参数：密码
        // 调用Service层执行登录逻辑
        User user = userService.login(username, password);
        if (user == null) {// 登录失败（用户名或密码错）
            return Result.error("用户名或密码错误");
        }

        // // 登录成功：生成JWT Token（用户身份凭证）
        String token = JwtUtil.generateToken(user.getId(), user.getUsername(), user.getRole());
	// 封装token到响应结果，返回给前端
        Map<String, String> res = new HashMap<>();
        res.put("token", token);
        return Result.success(res);
    }
}
```

## 🔑 第六步：JWT 工具类（`util/JwtUtil.java`）

生成和解析 JWT 令牌。Token 是用户登录后的 “身份凭证”，包含用户关键信息（加密且防篡改），前端后续请求需携带 token 证明已登录。

```java
package com.library.util;

import io.jsonwebtoken.*;

import java.util.Date;

public class JwtUtil {
    private static final String SECRET = "library_secret"; // 密钥
    private static final long EXPIRE = 1000 * 60 * 60 * 2; // 2小时

    // 生成Token：将用户ID、用户名、角色等信息存入token，用密钥签名
    public static String generateToken(Long userId, String username, String role) {
        return Jwts.builder()
                .claim("id", userId)
                .claim("username", username)
                .claim("role", role)
                .setExpiration(new Date(System.currentTimeMillis() + EXPIRE))
                .signWith(SignatureAlgorithm.HS256, SECRET)
                .compact();
    }

    / 解析Token：验证签名并提取用户信息
    public static Claims parseToken(String token) {
        return Jwts.parser().setSigningKey(SECRET).parseClaimsJws(token).getBody();
    }
}
```

## 🔑 第七步：拦截器（校验 Token）

拦截所有请求（除登录外），验证请求中的 token 是否有效，实现 “未登录禁止访问” 的鉴权功能，保障系统安全。

在 `config/LoginInterceptor.java`：

```java
package com.library.config;

import com.library.util.JwtUtil;
import io.jsonwebtoken.Claims;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

@Component // 标记为Spring组件
public class LoginInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) throws Exception {
        // 步骤1：从请求头获取token（前端需在header中携带Authorization: token）
        String token = request.getHeader("Authorization");
        if (token == null || token.isEmpty()) {// 无token → 未登录
            response.setStatus(401);// 返回401（未授权）
            return false;  // 拦截请求，不允许访问
        }
// 步骤2：解析token（验证签名和有效期）
        try {
            Claims claims = JwtUtil.parseToken(token);// 解析成功 → token有效
            request.setAttribute("user", claims);// 将用户信息存入request，供后续接口使用
            return true; // 放行请求
        } catch (Exception e) { // 解析失败（token无效/过期）
            response.setStatus(401);// 返回401
            return false;// 拦截请求
        }
    }
}
```

然后在 `WebMvcConfig.java` 注册：

```java
package com.library.config;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration // 标记为配置类
public class WebMvcConfig implements WebMvcConfigurer {

    @Autowired
    private LoginInterceptor loginInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/**") // 拦截所有请求
                .excludePathPatterns("/user/login"); // 登录不拦截
    }
}
```

## 🔑 第八步：Redis 优化

- **问题**：每次请求都要查数据库，压力大。
- **优化**：把登录后的 `userId → userInfo` 存 Redis，后续校验直接从 Redis 取，避免频繁查库。

示例：

```java
// 登录成功后缓存用户信息
redisTemplate.opsForValue().set("login:" + user.getId(), user, 2, TimeUnit.HOURS);
// 用户修改密码后
redisTemplate.delete("login:" + userId); // 删除旧缓存
```

拦截器里可以优先从 Redis 拿用户信息。

## 🔑 优化总结

1. **密码加密存储** → 使用 MD5 / BCrypt。
2. **认证优化** → JWT Token + Redis 缓存。
3. **扩展性** → 可以支持角色控制（admin/user 不同权限）。
4. **安全性** → Token 过期机制、Redis 缓存清理。

  ```java

  @Value("${jwt.secret}")
  private String secret;
  @Value("${jwt.expire}")

  ```





#### 1. 登录流程说明（体现对整体逻辑的理解）

“我们的登录功能采用‘用户名密码验证→生成 token→token 鉴权’的流程：

1. 前端提交用户名和密码，后端通过 Mapper 查询数据库获取用户信息；

2. 用 MD5 加密输入密码，与数据库中存储的加密密码对比，验证身份；

3. 验证通过后，用 JWT 生成包含用户 ID、角色的 token，返回给前端；

4. 后续请求需在 header 中携带 token，拦截器验证 token 有效性，未登录或 token 无效则拒绝访问。

   同时，通过 Redis 缓存用户信息，减少数据库查询，提升性能。”

#### 2. 安全设计说明（体现安全意识）

“我们在安全层面做了三点保障：

1. 密码加密存储：不存储明文，用 MD5 加密（后续计划升级为 BCrypt，更难破解）；
2. 身份认证：通过 JWT 生成 token，包含用户信息且防篡改，避免重复登录验证；
3. 权限控制：拦截器验证 token，未登录用户无法访问接口，后续可基于角色细化权限（如管理员才能操作图书管理）。”
