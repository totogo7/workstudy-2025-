## 数据库设计

系统需要支持：图书增删改查、借阅/归还、预约（预订）、逾期提醒、热门书缓存、前后端联调（Swagger）、单元测试覆盖后端逻辑。
 建模原则：规范化（防止冗余）、支持多副本（图书可能多本）、关注查询性能（分页、检索、借阅统计）、支持事务并发控制（借书场景避免超借）。

------

### ER 概览（文字版）

- Users (1) ←——（M） BorrowRecords (借阅记录) ——→ (1) BookCopies
- Books (1) ←——（M） BookCopies
- Books (M) ←——（M） Authors (通过 BookAuthors)
- Books (M) ←——（M） Categories (可用 BookCategory 或 book → category_id 单值)
- Users (1) ←——（M） Reservations（预约） ←—— BookCopies/Books
- Admin / Roles / User_Roles 用于权限（可选）

------

### 主要表设计说明（每张表都给字段、类型、说明、索引、建表 SQL）

> 采用 MySQL 8，InnoDB，字符集 utf8mb4。主键用 BIGINT UNSIGNED AUTO_INCREMENT；时间用 DATETIME(3) 或 TIMESTAMP；软删除用 `is_deleted` 或 `status` 字段控制。

#### 1) `users` — 用户表（学生/管理员共用）

用途：存储用户基本信息、认证字段、借阅的权限信息等。

```sql
CREATE TABLE `users` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username` VARCHAR(64) NOT NULL,
  `password` VARCHAR(128) NOT NULL, -- 存储 bcrypt/argon2 等哈希
  `email` VARCHAR(128),
  `phone` VARCHAR(32),
  `full_name` VARCHAR(64),
  `role` VARCHAR(32) DEFAULT 'user', -- 'user','admin' 等（可选用 user_roles 细分）
  `max_borrow` TINYINT UNSIGNED DEFAULT 5, -- 最大可借数量
  `status` TINYINT DEFAULT 1, -- 1:正常,0:禁用
  `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_users_username` (`username`),
  UNIQUE KEY `uk_users_email` (`email`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

索引：username/email 唯一；如需按 phone 查询加索引。`max_borrow` 可用于权限差异化。

#### 2) `books` — 图书主表（书目级信息）

用途：每本书的书目数据（ISBN、标题、摘要、出版社、总副本数统计等）

```sql
CREATE TABLE `books` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `isbn` VARCHAR(20) DEFAULT NULL,
  `title` VARCHAR(255) NOT NULL,
  `subtitle` VARCHAR(255) DEFAULT NULL,
  `summary` TEXT,
  `publisher` VARCHAR(128),
  `publish_date` DATE DEFAULT NULL,
  `total_copies` INT UNSIGNED DEFAULT 0, -- 总副本数统计（冗余，用触发器或应用维护）
  `available_copies` INT UNSIGNED DEFAULT 0, -- 可借副本数（快速查询）
  `cover_url` VARCHAR(512),
  `language` VARCHAR(32) DEFAULT 'zh',
  `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_books_isbn` (`isbn`),
  FULLTEXT KEY `ft_books_title_summary` (`title`, `summary`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

索引：isbn 唯一；对 title/summary 建 FULLTEXT（全文检索），对作者/类别通过关联表查询。

#### 5) `book_copies` — 图书副本/库存（物理或电子副本）

用途：每个实体副本或条目，用于借阅分配；也可将库存抽象为 `count`，但有副本记录时更便于追踪归还/损坏/遗失等。

```sql
CREATE TABLE `book_copies` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `book_id` BIGINT UNSIGNED NOT NULL,
  `barcode` VARCHAR(64) DEFAULT NULL, -- 条形码或副本唯一标识
  `copy_status` TINYINT NOT NULL DEFAULT 1, -- 1:可借,2:已借,3:损坏,4:丢失
  `location` VARCHAR(128) DEFAULT NULL,
  `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  KEY `idx_copies_bookid_status` (`book_id`, `copy_status`),
  CONSTRAINT `fk_copies_book` FOREIGN KEY (`book_id`) REFERENCES `books` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

设计说明：`available_copies` 字段在 `books` 与 `book_copies` 中都存在（冗余），用于快速查询；更新时需在事务中同步。

#### 6) `borrow_records` — 借阅记录（核心）

用途：记录借出/归还、到期与罚款信息。

```sql
CREATE TABLE `borrow_records` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id` BIGINT UNSIGNED NOT NULL,
  `copy_id` BIGINT UNSIGNED NOT NULL,   -- 如果按副本借
  `book_id` BIGINT UNSIGNED NOT NULL,   -- 冗余，便于查询
  `borrow_time` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `due_time` DATETIME(3) NOT NULL,
  `return_time` DATETIME(3) DEFAULT NULL,
  `status` TINYINT NOT NULL DEFAULT 1, -- 1:借出中,2:已归还,3:逾期已还,4:丢失
  `fine_amount` DECIMAL(10,2) DEFAULT 0.00,
  `renew_count` TINYINT UNSIGNED DEFAULT 0,
  `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  KEY `idx_br_user_status` (`user_id`, `status`),
  KEY `idx_br_copy` (`copy_id`),
  CONSTRAINT `fk_br_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_br_copy` FOREIGN KEY (`copy_id`) REFERENCES `book_copies` (`id`) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

说明：`due_time` 根据借期规则生成（例如 borrow_time + 30 days）。`status` 用于快速查找当前借出的记录（status=1）。`copy_id` 用 `FOR UPDATE` 锁定以避免并发借出同一副本。

#### 7) `reservations` — 预约表（用户预约图书）

用途：当没有可借副本时，用户可以预约；按预约顺序分配。

```sql
CREATE TABLE `reservations` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id` BIGINT UNSIGNED NOT NULL,
  `book_id` BIGINT UNSIGNED NOT NULL,
  `reserve_time` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `status` TINYINT NOT NULL DEFAULT 1, -- 1:等待,2:已通知,3:已取消,4:已过期
  `expire_time` DATETIME(3) DEFAULT NULL, -- 通知后保留期
  PRIMARY KEY (`id`),
  KEY `idx_res_book_status` (`book_id`, `status`, `reserve_time`),
  CONSTRAINT `fk_res_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_res_book` FOREIGN KEY (`book_id`) REFERENCES `books` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

预约调度：当有副本归还并且存在 `reservations` (status=1) 的记录，系统通知队列首用户并将 `status` 置为 `2` 并设置 `expire_time`。

### 视图 & 常用聚合（方便前端快速取数据）

例如一个 `book_summary` 视图，聚合书目与可借数量：

```sql
CREATE VIEW `book_summary` AS
SELECT b.id, b.title, b.isbn, b.publisher,
  b.total_copies, b.available_copies,
  IFNULL(br.borrowed_cnt, 0) as borrowed_cnt
FROM books b
LEFT JOIN (
   SELECT book_id, COUNT(*) AS borrowed_cnt
   FROM borrow_records WHERE status = 1
   GROUP BY book_id
) br ON b.id = br.book_id;
```

### 常用查询示例（便于你在后端实现 Mapper 时直接用）

1. 分页列出书籍（按标题/作者/分类搜索）：

```sql
SELECT b.* 
FROM books b
LEFT JOIN book_authors ba ON ba.book_id = b.id
LEFT JOIN authors a ON a.id = ba.author_id
LEFT JOIN book_categories bc ON bc.book_id = b.id
LEFT JOIN categories c ON c.id = bc.category_id
WHERE (b.title LIKE CONCAT('%',#{kw},'%') OR a.name LIKE CONCAT('%',#{kw},'%') OR b.isbn = #{isbn})
GROUP BY b.id
ORDER BY b.updated_at DESC
LIMIT #{offset}, #{size};
```

1. 查询某用户当前借出数：

```sql
SELECT COUNT(*) FROM borrow_records WHERE user_id = #{uid} AND status = 1;
```

1. 找到可借副本并锁定（借书核心步骤示例）：

```sql
-- 在事务中
SELECT id FROM book_copies
WHERE book_id = #{bookId} AND copy_status = 1
LIMIT 1
FOR UPDATE;

-- 若拿到 row，则 update copy_status = 2 并在 borrow_records 插入记录
```

1. 查找逾期未还并未通知的（用于定时任务）：

```sql
SELECT br.id, br.user_id, br.book_id, br.copy_id, br.due_time
FROM borrow_records br
WHERE br.status = 1 AND br.due_time < NOW()
-- 可联表 users 取联系方式用于发送提醒
```

### 并发控制：借书/还书事务流程（关键，给面试官看得清楚）

借书场景需要**防止并发超借**（两个请求同时看到 available_copies>0 并都借出同一副本）。两种常见实现策略：

#### A. 悲观锁（行级锁）

在事务中 `SELECT ... FOR UPDATE` 锁定要操作的 `book_copies` 或 `books` 行，随后更新并插入借阅记录，最后提交。

伪 SQL 流程：

```sql
START TRANSACTION;

-- 找一个可借副本并加锁
SELECT id FROM book_copies
WHERE book_id = #{bookId} AND copy_status = 1
LIMIT 1 FOR UPDATE;

-- 若无可借副本，返回失败（可转为 reservation）
-- 如果找到：
UPDATE book_copies SET copy_status = 2 WHERE id = #{copyId};

-- 更新 books.available_copies = available_copies - 1
UPDATE books SET available_copies = available_copies - 1 WHERE id = #{bookId};

-- 插入借阅记录
INSERT INTO borrow_records(user_id, copy_id, book_id, borrow_time, due_time, status)
VALUES(...);

COMMIT;
```

优缺点：实现简单且安全；但在高并发下会造成锁等待。适合并发不特别高的校园场景。

#### B. 乐观锁（版本号或库存计数）

在 `books` 表中维护 `available_copies` 与 `version`（或仅`available_copies`），更新时使用 `WHERE available_copies > 0 AND version = ?`，成功则提交，否则重试。

伪 SQL：

```sql
-- 读取 available_copies 与 version
SELECT available_copies, version FROM books WHERE id = #{bookId};

-- 如果 available_copies <= 0 则失败
-- 尝试更新（CAS 风格）
UPDATE books SET available_copies = available_copies - 1, version = version + 1
WHERE id = #{bookId} AND version = #{oldVersion} AND available_copies > 0;
-- 若 rows_affected == 1 则成功；否则重试或返回失败
```

优点：减少锁等待。缺点：需要处理冲突重试与副本分配（若使用 book_copies 也需同时分配具体副本）。

> 实务建议：如果你项目中 `book_copies` 有明确副本，采用悲观锁定单个副本 FOR UPDATE 是最直观也最容易讲清楚的方式；如果仅维护计数，采用乐观锁并结合 Redis/in-memory 队列也常见。

### Redis 缓存设计（快速查热门书、session、限流）

用途：缓存热门书目信息、缓存用户会话、实现预约队列、缓存搜索热词统计等。

示例键设计：

- `book:summary:{bookId}` -> 缓存书目 JSON（过期 10 分钟，更新时清除或写入时更新）
- `book:popular` -> 有序集合 ZSET，score 为借阅次数或访问次数（用于前端热门榜）
- `user:session:{token}` -> 存 session 或 JWT 黑名单（若使用 jwt）
- `reserve:queue:{bookId}` -> 列表或有序集合存放预约用户 id（按时间排序）
- `book:lock:{bookId}` -> 简单分布式锁键（如在无 DB 锁方案下临时防并发）

示例：把热门书加入 `ZINCRBY book:popular 1 {bookId}`，定时任务可以把 topN 拉出来并写回缓存或刷新 `book:summary`。

### 搜索建议（当数据量增大）

- 简单：MySQL FULLTEXT（对 title/summary）+ like 查询（小数据量可用）。
- 更强：Elasticsearch / OpenSearch，用于复杂权重、分词、联想搜索与高并发检索。
- 若短期实现，用 MySQL FULLTEXT 配合 `MATCH ... AGAINST`，注意设置分词与最小词长度。

------

### 备份与维护建议

- 定期备份 schema + 数据（mysqldump / xtrabackup）；对大表做分区策略（如 borrow_records 按年月分区）以优化历史查询。
- 对 `borrow_records`、`book_copies` 做合理的归档：历史超长可移到冷库表。
- 在 CI/CD 中加入 Flyway 或 Liquibase 管理数据库迁移脚本（版本化 schema）。

------

### 推荐的表字段和索引优化小贴士（面试时可以念）

- 经常查询的过滤字段（例如 `book_id,status`、`user_id,status`）都建立联合索引以避免回表。
- 对频繁排序字段（`updated_at`）考虑单字段索引以加速 ORDER BY + LIMIT 场景。
- FULLTEXT 对长文本检索比 LIKE 更高效，若短语匹配使用 boolean 模式。
- 外键在开发阶段帮助保证一致性，但生产高压下也可以选择应用层维护（视规模）。

------

### 例：借阅超时提醒的查询（供定时任务使用）

```sql
SELECT br.id, br.user_id, u.email, u.phone, b.title, br.due_time
FROM borrow_records br
JOIN users u ON u.id = br.user_id
JOIN books b ON b.id = br.book_id
WHERE br.status = 1 AND br.due_time < NOW() AND br.return_time IS NULL;
```

定时任务运行时把这些记录推入消息队列（RabbitMQ/Redis stream）发送邮件/SMS/系统通知，并更新 `borrow_records` 的 `status` 或添加 `remind_count` 字段记录是否已提醒。
