# 按阶段逐步实现（每一步要做的具体内容、产出、如何验证、注意点）

下面按我之前给出的 18 个阶段（0–17）逐一拆成 **可执行的任务清单**。每一小项都写清你要做什么、要新建哪些文件/代码、如何运行/验证、测试要点、面试时该怎么描述。你照着做、逐项打钩就能把项目从 MVP 做到工业化 —— 面试时讲起来既有深度又有工程感。

> 使用说明：优先完成阶段 0–6（MVP 路径），再做 7–11（稳定与测试），最后推进 12–17（部署、运维、安全、产品化）。
>  我用“任务 / 产出 / 验证 / 注意点 / 面试话术”五段格式来写每一步，方便你一边做一边复述。

# 第 4 阶段 — 用户与认证模块（注册/登录/JWT/Redis）

（你之前已完成基础，我在这里给出更细化步骤）

**任务**

- 完成用户表与 Mapper（插入、根据 username 查询）。
- 用 BCrypt 存密码；实现注册接口（校验用户名唯一）。
- JWT 生成/解析工具（`JwtUtil`），配置 secret 从 env 读入。
- 登录时生成 token，把 token 存 Redis（`login:{userId}`），实现登出删除 Redis key。
- 拦截器 `AuthInterceptor`：解析 header 的 `Authorization: Bearer <token>`，校验 Redis 中的 token（支持立即失效）。
- 实现 refresh token 机制（可选）：短 access + 长 refresh。

**具体文件**

- `AuthController`, `UserService`, `JwtUtil`, `AuthInterceptor`, `WebMvcConfig`（拦截器注册）

**验证**

- curl / Postman 完成 register→login→访问受保护接口→logout→再访问失败。
- 检查 Redis `GET login:{userId}` 有 token。

**测试**

- 单测 UserService（Mockito）验证 register/login 的分支（bcrypt vs legacy md5 转换）。
- 集成测试：`@SpringBootTest` 登陆后带 token 访问受保护接口。

**注意点**

- secret 不要硬编码，生产使用 secret manager。
- 登录失败次数限制（redis 计数）与验证码防暴力破解（后续）。

**面试话术**

> “我用 JWT + Redis 做认证，兼顾了无状态 token 的扩展性和登出/黑名单的即时性。”

# 第 6 阶段 — 库存、副本与并发借书流程（关键）

**任务**

- 选择库存策略：**副本表**（推荐，粒度更细）或 **计数字段**（简单）。
- 设计并实现借书流程（事务）：
  1. 检查用户是否有未还超限（业务校验）
  2. 查询 `book_copies` 表中 `copy_status = available` 的一条并行锁（`SELECT id FROM book_copies WHERE book_id=? AND copy_status=1 LIMIT 1 FOR UPDATE`）
  3. 若存在，更新 `copy_status=borrowed`；插入 `borrow_records`；更新 `books.available_copies = available_copies - 1`（或触发器）
  4. commit
- 还书：在事务里更新 copy_status=available，更新 borrow_records return_time，更新 books.available_copies++，若存在 reservation 列表触发保留通知
- 预约：实现 reservations 表和排队逻辑（FIFO）

**文件**

- `BorrowController`, `BorrowService`（@Transactional）, `BookCopyMapper`

**验证**

- 写并发集成测试：用两个线程并发调用 borrow 接口，断言只有一个成功。推荐用 Testcontainers 真 MySQL 运行测试以确保 `FOR UPDATE` 行为正确。
- 手工测试：在前端连续发送两个借书请求观察结果。

**测试**

- 并发集成测试（重点）
- 回归测试（借还成功/失败路径）

**注意点**

- `FOR UPDATE` 需要走索引以避免全表锁（确保 WHERE 使用索引字段）。
- 在高并发可以引入 Redis 预减库存 + 异步最终一致（复杂），先用 DB 事务保证正确性。

**面试话术**

> “我用事务 + 行级锁（SELECT ... FOR UPDATE）保证并发场景下只有一个请求能拿到副本；并写了多线程集成测试复现 race 条件。”

# 第 8 阶段 — 缓存与性能优化（Redis）

**任务**

- 设计缓存策略（Cache-Aside）：read => check Redis `book:summary:{id}`；miss => DB -> write Redis（TTL）。
- 热点计数：`ZINCRBY book:popular {bookId} 1`。
- 防穿透：布隆过滤器或缓存空对象（短 TTL）。
- 防雪崩：随机 TTL、预热热点。
- 在读密集接口（首页热门、详情）加缓存。

**产出**

- `BookCacheService`, Redis keys doc (`docs/redis_keys.md`)

**验证**

- 比较缓存命中与未命中时的响应延迟；模拟缓存击穿场景。

**测试**

- 缓存一致性测试（update book 后缓存失效是否正确）。

**注意点**

- 更新/删除时要做 cache invalidation（先 DB 再删除缓存或用双写策略谨慎处理）。

**面试话术**

> “我用 Cache-Aside 保证一致性并用 ZSET 做热榜统计，同时用布隆过滤器防穿透。”
