# MVP（先做完这部分能跑起来并能面试 demo）

必做（优先级高）：

1. 环境搭建（IDEA、MySQL、Redis、本地运行脚本）
2. 数据库与建表（users, books, book_copies, borrow_records, reservations）
3. 后端骨架（Spring Boot + MyBatis）与基本模块：用户登录（JWT）、图书 CRUD、借书/还书（事务）
4. 前端最小页面：登录、图书列表、图书详情、借阅记录、借书按钮（Vue + Element）
5. 基础测试：单元测试 + Postman 接口集合
6. README + 启动脚本（docker-compose 可启动 MySQL/Redis + 后端）

完成这些，你就能现场演示：用户登录 → 搜书 → 借书 → 查看借阅记录（并展示事务与错误处理）。

## 阶段 4 — 用户与认证模块（产出：完整用户体系与认证）

- 任务
  - `users` 表、注册接口（可选）、登录接口（密码 hash：BCrypt）
  - JWT 实现（access token） + Refresh Token 设计
  - Redis 存会话/黑名单以支持登出（立即失效 token）
  - 拦截器/过滤器实现鉴权（解析 JWT，放入 `SecurityContext` 或 request attribute）
  - 用户角色/权限（admin/user）与注解方式权限校验（简易 AOP）
- 产出
  - `AuthController`, `UserService`, `JwtUtil`, `AuthInterceptor`、Redis 配置
- 验收
  - 登录返回 token；使用 token 访问受保护接口成功；登出能立刻失效

- 任务

  - DTO 校验（Hibernate Validator）和统一错误提示

## 阶段 6 — 库存与副本（book_copies）与借阅流程（产出：并发安全借阅流程）

- 任务
  - `book_copies` 表设计（副本粒度）或简单 inventory count 两种策略（建议先用副本表）
  - 借书流程设计：检查用户可借数量、查询可借副本、在事务内 `SELECT ... FOR UPDATE` 锁定副本、更新副本状态、插入 `borrow_records`、更新 books.available_copies（若有）
  - 还书流程：更新副本状态、更新借阅记录 `return_time`、计算逾期罚款（可选）
  - 预约（reservations）实现：当无可借副本时允许预约，归还时通知队列首位并设置保留期
- 产出
  - `BorrowController`, `BorrowService`（事务），Mapper SQL（含 FOR UPDATE）
- 验收
  - 并发测试：两个并发请求借同一 bookId，应只有一个成功（写并发测试用例）

## 阶段 7 — 搜索与全文检索（产出：高质量搜索体验）

- 任务
  - 短期：MySQL FULLTEXT（或 LIKE）实现基本搜索
  - 长期/可选：集成 Elasticsearch（或 OpenSearch）用于分词、权重、智能排序、联想搜索（autocomplete）
  - 搜索 API：支持按标题、作者、分类、ISBN、可借状态筛选与分页
- 产出
  - `SearchController` + ES 索引配置（若接入 ES）
- 验收
  - 搜索响应时间合理；示例查询结果与预期相关度高

------

## 阶段 8 — 缓存与性能优化（产出：Redis 缓存层设计）

- 任务
  - Cache-Aside 策略：`book:summary:{id}` 缓存书目信息、`book:popular` ZSET 统计热度
  - 热点保护（布隆过滤器防穿透、随机过期防雪崩）
  - Redis 键设计与失效策略（过期策略、写入/更新时的 cache invalidation）
  - 在高读场景下把热门页面/结果缓存到 Redis 或生成静态片段
- 产出
  - `BookCacheService.java`、Redis 配置、缓存测试脚本
- 验收
  - 热门图书接口在缓存命中时响应显著变快；并发下无严重缓存不一致

- 产出
  - `ReminderJob`, `NotificationService`, MQ 配置
- 验收
