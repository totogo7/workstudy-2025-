# 要点回顾（最终交付）

1. Cache-Aside 模式为主：读时先查 Redis，miss 则从 DB 读后写缓存；写操作（create/update/delete）时先写 DB 再删除/更新缓存（保证一致性）。
2. 热点统计：用 Redis ZSET `book:popular` 记录浏览/搜索/借阅热度，支持热点榜单。
3. 防穿透：对空结果缓存短 TTL；可选布隆过滤器提示（若启用 RedisBloom）。
4. 防雪崩：加随机 TTL；缓存重建采用分布式锁（SETNX + expire）避免缓存击穿期间大量并发穿透 DB。
5. 提供 `BookCacheService`，并改造 `BookService` 的 getById / list 热点接口去使用缓存。
6. 提供运维/调试命令与测试脚本。

# 1) Redis keys 设计（放在 docs）

创建 `library-backend/src/main/resources/docs/redis_keys.md`，内容如下（复制粘贴）：

```
Redis Key Design (Library Management)

1. book:detail:{bookId} -> string or hash
   - stores serialized Book JSON (cache-aside)
   - TTL: 30m +/- random(0~300s) to prevent avalanche

2. book:search:{q_hash} -> string (search results)
   - cache search results for hot searches
   - TTL: short (5m) for dynamic content

3. book:popular -> ZSET
   - key: "book:popular"
   - member: bookId, score: hit count (ZINCRBY per view/borrow/search)
   - used for hot list (top N)

4. bloom:books -> Bloom filter (optional, requires RedisBloom)
   - used to quickly filter non-existent ids (avoid DB hit)

5. lock:book:detail:{bookId} -> string
   - distributed lock (SETNX) for cache rebuild
   - expire short (5-10s)

Notes:
- Cache invalidation strategy: after DB write (create/update/delete), delete the corresponding cache keys (book:detail:{id}, related search keys).
- Use randomized TTL: TTL = base + Random(0, jitterSeconds).
- For search keys, use a deterministic hash of query to form key (e.g., md5(query)).
```

# 2) Redis 配置回顾（确认 RedisTemplate bean）

如果你之前已经有 `RedisConfig.java`（我之前给过），确认里面暴露 `RedisTemplate<String, Object>`。若没有，请加入/替换为以下内容（文件路径：`src/main/java/com/library/config/RedisConfig.java`）：

```java
package com.library.config;

import com.library.util.JwtUtil;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Bean;
import org.springframework.data.redis.connection.lettuce.LettuceConnectionFactory;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.serializer.StringRedisSerializer;

@Configuration
public class RedisConfig {

    @Value("${spring.redis.host}")
    private String redisHost;
    @Value("${spring.redis.port}")
    private int redisPort;

    @Bean
    public LettuceConnectionFactory redisConnectionFactory() {
        return new LettuceConnectionFactory(redisHost, redisPort);
    }

    @Bean
    public RedisTemplate<String, Object> redisTemplate(LettuceConnectionFactory lcf) {
        RedisTemplate<String, Object> rt = new RedisTemplate<>();
        rt.setConnectionFactory(lcf);
        // use String serializer for keys
        rt.setKeySerializer(new StringRedisSerializer());
        rt.setHashKeySerializer(new StringRedisSerializer());
        rt.setValueSerializer(new StringRedisSerializer()); // store JSON as String
        rt.afterPropertiesSet();
        return rt;
    }
}
```

# 3) BookCacheService（核心实现）

创建文件 `library-backend/src/main/java/com/library/cache/BookCacheService.java`：

```java
package com.library.cache;

import com.fasterxml.jackson.core.JsonProcessingException;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.library.entity.Book;
import com.library.mapper.BookMapper;
import org.springframework.stereotype.Service;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.core.ZSetOperations;
import org.springframework.data.redis.core.ValueOperations;

import javax.annotation.Resource;
import java.time.Duration;
import java.util.concurrent.TimeUnit;
import java.util.Random;

@Service
public class BookCacheService {

    private static final String BOOK_KEY_PREFIX = "book:detail:";
    private static final String BOOK_POPULAR_KEY = "book:popular";
    private static final String LOCK_PREFIX = "lock:book:detail:";

    private static final long BASE_TTL_SECONDS = 30 * 60; // 30 minutes
    private static final int TTL_JITTER_SECONDS = 300; // up to +5 minutes

    private static final long EMPTY_OBJ_TTL_SECONDS = 60; // cache empty result 60s to prevent penetration

    @Resource
    private RedisTemplate<String, Object> redisTemplate;

    @Resource
    private BookMapper bookMapper;

    private ObjectMapper mapper = new ObjectMapper();
    private Random rand = new Random();

    public Book getBookByIdCached(Long bookId) {
        String key = BOOK_KEY_PREFIX + bookId;
        ValueOperations<String, Object> ops = redisTemplate.opsForValue();
        Object cached = ops.get(key);
        if (cached != null) {
            try {
                String json = cached.toString();
                if ("__EMPTY__".equals(json)) return null;
                return mapper.readValue(json, Book.class);
            } catch (Exception e) {
                // fallthrough to db
            }
        }

        // cache miss -> try to acquire rebuild lock
        String lockKey = LOCK_PREFIX + bookId;
        Boolean got = redisTemplate.opsForValue().setIfAbsent(lockKey, "1", Duration.ofSeconds(10));
        if (Boolean.TRUE.equals(got)) {
            try {
                // load from db
                Book b = bookMapper.findById(bookId);
                if (b == null) {
                    // cache null placeholder to prevent penetration
                    ops.set(key, "__EMPTY__", EMPTY_OBJ_TTL_SECONDS, TimeUnit.SECONDS);
                    return null;
                }
                try {
                    String json = mapper.writeValueAsString(b);
                    long ttl = BASE_TTL_SECONDS + rand.nextInt(TTL_JITTER_SECONDS);
                    ops.set(key, json, ttl, TimeUnit.SECONDS);
                } catch (JsonProcessingException ex) {
                    // ignore serialization error, but return b
                }
                return b;
            } finally {
                redisTemplate.delete(lockKey);
            }
        } else {
            // someone else is rebuilding cache; fallback to DB read (or sleep briefly then read cache)
            try {
                // small sleep to wait for cache rebuild
                Thread.sleep(50);
            } catch (InterruptedException e) {}
            Object after = ops.get(key);
            if (after != null) {
                try {
                    String json = after.toString();
                    if ("__EMPTY__".equals(json)) return null;
                    return mapper.readValue(json, Book.class);
                } catch (Exception ignore){}
            }
            // final fallback to DB
            return bookMapper.findById(bookId);
        }
    }

    public void invalidateBookCache(Long bookId) {
        String key = BOOK_KEY_PREFIX + bookId;
        redisTemplate.delete(key);
    }

    public void incrementHotScore(Long bookId, double score) {
        ZSetOperations<String, Object> zops = redisTemplate.opsForZSet();
        zops.incrementScore(BOOK_POPULAR_KEY, String.valueOf(bookId), score);
    }

    public java.util.List<Long> topNPopular(int n) {
        ZSetOperations<String, Object> zops = redisTemplate.opsForZSet();
        java.util.Set<Object> set = zops.reverseRange(BOOK_POPULAR_KEY, 0, n - 1);
        java.util.List<Long> result = new java.util.ArrayList<>();
        if (set != null) {
            for (Object o : set) {
                try { result.add(Long.valueOf(o.toString())); } catch (Exception ex) {}
            }
        }
        return result;
    }

    // helper to cache search results (optional)
    public void cacheSearchResult(String key, String json, long ttlSeconds) {
        redisTemplate.opsForValue().set(key, json, ttlSeconds, TimeUnit.SECONDS);
    }

    public Object getCachedSearchResult(String key) {
        return redisTemplate.opsForValue().get(key);
    }
}
```

**说明（要点）**

- `getBookByIdCached` 使用 cache-aside + distributed lock via `SETNX` (`setIfAbsent`) 避免缓存击穿。
- 空对象缓存 `"__EMPTY__"` 防穿透（短 TTL）。
- 缓存 TTL 带 jitter，防雪崩。
- `incrementHotScore` 用 ZSET 做热度统计（`book:popular`），在页面被查看/借阅/搜索时调用。

# 4) 把 BookServiceImpl 改造为使用缓存

打开 `library-backend/src/main/java/com/library/service/impl/BookServiceImpl.java`，在 `getById` 改为使用 `BookCacheService`（保留原 DB fallback）。

示例修改（关键片段）：

```java
// 注入
@Resource
private BookCacheService bookCacheService;

@Override
public Book getById(Long id) {
    // use cache
    Book b = bookCacheService.getBookByIdCached(id);
    // if found, increment hot score
    if (b != null) {
        bookCacheService.incrementHotScore(id, 1);
    }
    return b;
}

@Override
public Book create(Book book) {
    // db write
    bookMapper.insert(book);
    // optional: create copies...
    // invalidate cache (just in case)
    bookCacheService.invalidateBookCache(book.getId());
    return book;
}

@Override
public Book update(Long id, Book book) {
    book.setId(id);
    bookMapper.update(book);
    // invalidate cache – next read will rebuild
    bookCacheService.invalidateBookCache(id);
    return bookMapper.findById(id);
}

@Override
public boolean delete(Long id) {
    int r = bookMapper.deleteById(id);
    if (r == 1) {
        bookCacheService.invalidateBookCache(id);
        // also remove from popular zset
        redisTemplate.opsForZSet().remove("book:popular", String.valueOf(id));
        return true;
    }
    return false;
}
```

> 注意：上面 `redisTemplate` used in delete; 你可以把删除 ZSet 的逻辑放到 `BookCacheService` 执行。确保 `BookCacheService` 和 `BookServiceImpl` 没有循环依赖。

# 6) 分布式锁工具（可选 helper）

把下面放 `src/main/java/com/library/cache/CacheLockUtil.java`（简单实现）：

```java
package com.library.cache;

import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.core.ValueOperations;

import java.time.Duration;

public class CacheLockUtil {

    public static boolean tryLock(RedisTemplate<String, Object> rt, String key, long expireSeconds) {
        Boolean got = rt.opsForValue().setIfAbsent(key, "1", Duration.ofSeconds(expireSeconds));
        return Boolean.TRUE.equals(got);
    }

    public static void unlock(RedisTemplate<String, Object> rt, String key) {
        rt.delete(key);
    }
}
```

# 11) 面试讲法（如何把缓存这块讲得既专业又简洁）

- 开场一句：

  > “我用 Cache-Aside 模式把热点数据缓存到 Redis，补充了热度统计与保护策略，既保证一致性也提升了读取性能。”

- 技术细节要点（条理化讲）：

  1. 读：先 Redis，再 DB（miss 后写回 cache）；空结果短 TTL 防穿透。
  2. 写：DB 写成功后立即删除/更新 cache，避免读到脏数据。
  3. 缓存击穿保护：使用分布式锁（setIfAbsent）重建缓存，避免大量并发穿透 DB。
  4. 热点：用 ZSET `book:popular` 增量计数，支持热榜与预热。
  5. 难点/权衡：TTL 随机化与空对象缓存的时间权衡；RedisBloom 可进一步减少 DB 查无结果时的请求。

- 如果被追问为什么不用 write-through / write-back：

  > “Cache-Aside 最简单安全，写操作走 DB 为准；write-back 增加复杂性与丢失风险，不适合关键业务（借书/库存）。”
