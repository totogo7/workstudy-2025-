# 概览（目标）

- 定时任务 `ReminderJob`：
  - 定期（每小时）扫描：即将到期（例如 3 天内到期）的借阅记录 → 发送“到期提醒”；
  - 扫描已逾期的借阅记录 → 发送“逾期提醒”。
- 通知渠道：
  - 站内消息（写入 `messages` 表，用户在前端查看）；
  - 邮件（通过 JavaMailSender，开发环境可用 Mailtrap 或直接打印到日志）；
  - （可选）异步 MQ（RabbitMQ）替代直接发送，支持重试 / DLQ（我在后面给出可选示例）。
- 异步模型：`NotificationService` 将发送任务异步执行并记录结果 `notification_logs`（用于审计/重试）。
- 提供 REST API：`GET /api/notifications`（分页）供前端拉站内消息。

# 1) 数据库迁移（Flyway） — 新表：messages 与 notification_logs

新建文件（路径）
 `library-backend/src/main/resources/db/migration/V5__messages_and_notifications.sql`

```sql
-- V5__messages_and_notifications.sql
CREATE TABLE IF NOT EXISTS messages (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  title VARCHAR(255) NOT NULL,
  content TEXT NOT NULL,
  channel VARCHAR(32) NOT NULL COMMENT 'in_app|email|sms',
  status VARCHAR(32) DEFAULT 'pending' COMMENT 'pending|sent|failed',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  sent_at TIMESTAMP NULL,
  extra JSON NULL,
  CONSTRAINT fk_messages_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS notification_logs (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  message_id BIGINT,
  channel VARCHAR(32),
  attempt INT DEFAULT 0,
  last_error TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_nl_msg FOREIGN KEY (message_id) REFERENCES messages(id) ON DELETE SET NULL
);
```

> 说明：`messages` 用作站内消息与发送记录，`notification_logs` 记录每次发送尝试与错误，便于排查与重试。

## 实现（异步 + JavaMailSender）

路径：`library-backend/src/main/java/com/library/service/impl/NotificationServiceImpl.java`

```java
package com.library.service.impl;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.library.entity.Message;
import com.library.entity.NotificationLog;
import com.library.mapper.MessageMapper;
import com.library.mapper.NotificationLogMapper;
import com.library.service.NotificationService;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.mail.MailException;
import org.springframework.mail.SimpleMailMessage;
import org.springframework.mail.javamail.JavaMailSender;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;
import org.springframework.stereotype.Service;

import javax.annotation.Resource;
import java.time.LocalDateTime;

@Service
public class NotificationServiceImpl implements NotificationService {

    @Resource
    private MessageMapper messageMapper;
    @Resource
    private NotificationLogMapper logMapper;
    @Resource
    private JavaMailSender mailSender;

    private ObjectMapper mapper = new ObjectMapper();

    // thread pool for async sends
    private ThreadPoolTaskExecutor executor;

    @Value("${library.notify.email-from}")
    private String emailFrom;

    public NotificationServiceImpl() {
        executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(8);
        executor.setQueueCapacity(100);
        executor.initialize();
    }

    @Override
    public void notifyDueReminder(Long userId, String title, String content, boolean sendEmail) {
        // in-app
        sendMessage(userId, "in_app", title, content, true);
        if (sendEmail) {
            sendMessage(userId, "email", title, content, true);
        }
    }

    @Override
    public void sendMessage(Long userId, String channel, String title, String content, boolean async) {
        Message m = new Message();
        m.setUserId(userId);
        m.setChannel(channel);
        m.setTitle(title);
        m.setContent(content);
        m.setStatus("pending");
        try {
            m.setExtra(mapper.writeValueAsString(new Object())); // placeholder
        } catch (Exception e) {}
        messageMapper.insert(m);

        if ("in_app".equals(channel)) {
            // in_app is created in DB, mark pending; deliver is trivial (frontend will pull)
            // We can mark sent immediately
            messageMapper.updateStatus(m.getId(), "sent", java.sql.Timestamp.valueOf(LocalDateTime.now()));
            // log
            NotificationLog nl = new NotificationLog();
            nl.setMessageId(m.getId());
            nl.setChannel("in_app");
            nl.setAttempt(1);
            nl.setLastError(null);
            logMapper.insert(nl);
            return;
        }

        // email or other channels: send async
        Runnable task = () -> {
            try {
                if ("email".equals(channel)) {
                    sendEmail(m, title, content);
                } else {
                    // placeholder for sms or other
                }
                messageMapper.updateStatus(m.getId(), "sent", java.sql.Timestamp.valueOf(LocalDateTime.now()));
                NotificationLog nl = new NotificationLog();
                nl.setMessageId(m.getId());
                nl.setChannel(channel);
                nl.setAttempt(1);
                nl.setLastError(null);
                logMapper.insert(nl);
            } catch (Exception ex) {
                // record failure
                NotificationLog nl = new NotificationLog();
                nl.setMessageId(m.getId());
                nl.setChannel(channel);
                nl.setAttempt(1);
                nl.setLastError(ex.getMessage());
                logMapper.insert(nl);
                messageMapper.updateStatus(m.getId(), "failed", null);
            }
        };

        if (async) executor.submit(task); else task.run();
    }

    private void sendEmail(Message m, String subject, String body) {
        // In dev, JavaMailSender config may be Mailtrap / or log only
        SimpleMailMessage mail = new SimpleMailMessage();
        // lookup user's email? Here we assume user email retrieval elsewhere; for demo use userId -> email placeholder
        String toEmail = lookupEmailByUserId(m.getUserId());
        if (toEmail == null) {
            throw new RuntimeException("user email not found");
        }
        mail.setTo(toEmail);
        mail.setFrom(emailFrom);
        mail.setSubject(subject);
        mail.setText(body);
        try {
            mailSender.send(mail);
        } catch (MailException me) {
            throw me;
        }
    }

    private String lookupEmailByUserId(Long userId) {
        // TODO: call UserMapper to get user email (we used username/password earlier; let's assume users table has email)
        // For demo, build email from username or return placeholder
        // Implement properly: inject UserMapper and query email column.
        return "test+user" + userId + "@example.com";
    }
}
```

> 注意：实际应从 `users` 表读取真实 email；这里为展示流程用 placeholder。你可以注入 `UserMapper` 并在 users 表新增 `email` 列（Flyway migration）再替换 `lookupEmailByUserId`。

# 5) 定时任务 ReminderJob（扫描借阅记录并调用 NotificationService）

路径：`library-backend/src/main/java/com/library/job/ReminderJob.java`

```java
package com.library.job;

import com.library.entity.BorrowRecord;
import com.library.mapper.BorrowRecordMapper;
import com.library.service.NotificationService;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

import javax.annotation.Resource;
import java.time.LocalDateTime;
import java.util.List;

@Component
public class ReminderJob {

    @Resource
    private BorrowRecordMapper borrowRecordMapper;

    @Resource
    private NotificationService notificationService;

    @Value("${library.notify.reminder-days-before:3}")
    private int daysBefore;

    // 每小时运行一次（cron 表达式），也可改为每天某个时间
    @Scheduled(cron = "${library.notify.reminder-cron}")
    public void runReminder() {
        try {
            // 1. 到期提醒：借书 due_time 在 now .. now + daysBefore (inclusive)
            LocalDateTime now = LocalDateTime.now();
            LocalDateTime soon = now.plusDays(daysBefore);

            List<BorrowRecord> toRemind = borrowRecordMapper.findDueBetween(now, soon);
            for (BorrowRecord br : toRemind) {
                String title = "图书即将到期提醒";
                String body = String.format("您借阅的书（bookId=%d）将于 %s 到期，请及时归还或续借。", br.getBookId(), br.getDueTime().toString());
                // in_app + email
                notificationService.notifyDueReminder(br.getUserId(), title, body, true);
            }

            // 2. 逾期提醒：due_time < now and status == borrowed
            List<BorrowRecord> overdue = borrowRecordMapper.findOverdue(now);
            for (BorrowRecord br : overdue) {
                String title = "图书逾期提醒";
                String body = String.format("您借阅的书（bookId=%d）已于 %s 逾期，请尽快归还并联系管理员。", br.getBookId(), br.getDueTime().toString());
                notificationService.notifyDueReminder(br.getUserId(), title, body, true);
            }
        } catch (Exception ex) {
            ex.printStackTrace();
            // 生产里记录日志并上报监控
        }
    }
}
```

> 需要在 `BorrowRecordMapper` 中添加查询方法 `findDueBetween` 和 `findOverdue`。

# 7) 用户消息接口（前端拉取消息）

`NotificationController.java`（路径：`library-backend/src/main/java/com/library/controller/NotificationController.java`）

```java
package com.library.controller;

import com.library.common.Result;
import com.library.entity.Message;
import com.library.mapper.MessageMapper;
import org.springframework.web.bind.annotation.*;

import javax.annotation.Resource;
import javax.servlet.http.HttpServletRequest;
import java.util.List;

@RestController
@RequestMapping("/api/notifications")
public class NotificationController {

    @Resource
    private MessageMapper messageMapper;

    // GET /api/notifications?page=1&size=10
    @GetMapping
    public Result<List<Message>> list(@RequestParam(defaultValue = "1") int page,
                                      @RequestParam(defaultValue = "10") int size,
                                      HttpServletRequest req) {
        // get userId from request attribute (AuthInterceptor 设置)
        Object uidObj = req.getAttribute("userId");
        if (uidObj == null) return Result.error("not authenticated");
        Long userId = Long.valueOf(uidObj.toString());
        int offset = (page - 1) * size;
        List<Message> msgs = messageMapper.findByUserId(userId, offset, size);
        return Result.success(msgs);
    }
}
```

# 10) 扩展（可选，面试亮点）

1. **异步可靠队列（RabbitMQ/Kafka）**
   - 在 `sendMessage` 中把 message 写 DB 后发送到 MQ（`notifications` 队列），然后独立消费者 `NotificationWorker` 从队列拉取并执行发送（邮件/SMS）。消费失败则重试并写 `notification_logs`，失败太多进入 DLQ 供人工处理。
   - 优点：高可靠、解耦、能水平扩展。缺点：增加运维复杂度（队列系统）。
2. **重试策略与告警**
   - 对失败发送引入指数退避重试（maxAttempt 3），失败后写入 DLQ 并发送告警到 Slack/邮件给运维。
   - 用 `notification_logs` 统计失败率并报警。
3. **用户偏好设置**
   - 在 `users` 表或单独 `user_notifications` 表存储用户接收偏好（是否接收邮件/短信/站内）。ReminderJob 根据偏好决定是否调用 email/sms。
4. **短信渠道**
   - 接入第三方 SMS（阿里云/华为/腾讯云），通常通过 HTTP API 发起请求并解析响应，注意签名与限流。
5. **国际化 & 模版化**
   - 用 Thymeleaf 或 FreeMarker 管理邮件模板和多语言支持（subject/body 模板）。
