# 一、单元测试（JUnit5 + Mockito）

目标：覆盖业务逻辑（不触及 DB/Redis），快速、稳定、可在 CI 并行跑。

## 依赖（pom.xml）

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-test</artifactId>
  <scope>test</scope>
</dependency>
<dependency>
  <groupId>org.mockito</groupId>
  <artifactId>mockito-junit-jupiter</artifactId>
  <scope>test</scope>
</dependency>
```

## 示例：BookService 单元测试

文件：`library-backend/src/test/java/com/library/unit/BookServiceUnitTest.java`

```java
package com.library.unit;

import com.library.entity.Book;
import com.library.mapper.BookMapper;
import com.library.service.BookService;
import com.library.service.impl.BookServiceImpl;
import org.junit.jupiter.api.*;
import org.mockito.*;
import static org.mockito.Mockito.*;
import static org.junit.jupiter.api.Assertions.*;

class BookServiceUnitTest {

    @Mock
    private BookMapper bookMapper;

    private BookServiceImpl bookService;

    @BeforeEach
    void setup() {
        MockitoAnnotations.openMocks(this);
        bookService = new BookServiceImpl();
        bookService.setBookMapper(bookMapper); // add setter or use constructor injection
    }

    @Test
    void create_setsDefaultAvailableCopies() {
        Book b = new Book();
        b.setTitle("t");
        b.setTotalCopies(3);
        when(bookMapper.insert(any())).thenAnswer(inv -> {
            Book arg = inv.getArgument(0);
            arg.setId(1L);
            return 1;
        });

        Book created = bookService.create(b);
        assertNotNull(created.getId());
        assertEquals(3, created.getAvailableCopies());
        verify(bookMapper, times(1)).insert(any());
    }
}
```

> 小技巧：Service 实现若使用 `@Resource` 注入，给测试类提供 package-private setter 或构造函数注入更易于测试。

# 二、集成测试（SpringBootTest + Testcontainers + Flyway）

目标：启动真实 MySQL + Redis 容器，自动执行 Flyway migration，验证事务、SQL `FOR UPDATE` 行为、缓存逻辑等（最关键——并发借书测试）。

## 依赖（pom.xml）

```xml
<dependency>
  <groupId>org.testcontainers</groupId>
  <artifactId>mysql</artifactId>
  <version>1.17.6</version>
  <scope>test</scope>
</dependency>
<dependency>
  <groupId>org.testcontainers</groupId>
  <artifactId>junit-jupiter</artifactId>
  <version>1.17.6</version>
  <scope>test</scope>
</dependency>
```

## 关键点：在测试里用 Testcontainers 的 MySQL，并在 `@BeforeAll` 用 Flyway migrate 到该 DB

示例文件：`library-backend/src/test/java/com/library/integration/IntegrationTestBase.java`

```java
package com.library.integration;

import org.junit.jupiter.api.BeforeAll;
import org.springframework.boot.test.context.SpringBootTest;
import org.testcontainers.containers.MySQLContainer;
import org.flywaydb.core.Flyway;

@SpringBootTest
public abstract class IntegrationTestBase {

    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
            .withDatabaseName("testdb")
            .withUsername("test")
            .withPassword("test");

    @BeforeAll
    public static void beforeAll() {
        mysql.start();
        // Run Flyway against this container
        Flyway flyway = Flyway.configure()
                .dataSource(mysql.getJdbcUrl(), mysql.getUsername(), mysql.getPassword())
                .locations("classpath:db/migration")
                .load();
        flyway.migrate();

        System.setProperty("spring.datasource.url", mysql.getJdbcUrl());
        System.setProperty("spring.datasource.username", mysql.getUsername());
        System.setProperty("spring.datasource.password", mysql.getPassword());
    }
}
```

然后具体并发测试（你以前有 `BorrowConcurrencyTest`，把其改为继承 `IntegrationTestBase` 并使用真实 insert 方法）——重点是确保 Flyway 已迁移。

## 示例断言场景：并发借书

文件：`library-backend/src/test/java/com/library/integration/BorrowConcurrencyIT.java`
 （类似之前提供的代码，但要确保 `insert` mappers exist; Testcontainers will run migrations）

# 三、接口自动化（Postman + Newman）

目标：对关键接口写集合（auth→books→borrow→me），能在 CI 用 Newman 执行回归。

## 1) 准备 Postman collection

- 在 Postman 中创建请求序列：
  1. POST `/api/auth/register` (user alice)
  2. POST `/api/auth/login` -> extract token
  3. GET `/api/books` (list)
  4. POST `/api/books` (create) — admin token
  5. POST `/api/borrow` (borrow)
  6. GET `/api/me` (get current user data)
- 导出 `postman_collection.json` 放到 `test-scripts/`

## 2) 在 CI 使用 Newman 运行

安装 Newman（CI 环节里使用 npm image）：

```bash
npm install -g newman
newman run test-scripts/postman_collection.json -e test-scripts/postman_env.json
```

在 collection 里用 Postman tests (JS) 写断言，例如：

```js
pm.test("login success", function () {
  pm.response.to.have.jsonBody('code', 1);
});
```

# 五、性能测试（k6）

目标：模拟并发借书和搜索负载以找瓶颈。注意并发借书会实际修改 DB，要在 CI 使用隔离的测试环境。

## 安装 k6（本地或 CI runner）

参见 k6 docs；命令行工具 `k6`。

## 示例：`test-scripts/k6/borrow-load.js`

```js
import http from 'k6/http';
import { check, sleep } from 'k6';
import { SharedArray } from 'k6/data';

export let options = {
  vus: 50,
  duration: '30s',
};

const USERS = new SharedArray('users', function() {
  return [{username: 'user1', password: 'pass1'}, /* ... */];
});

export default function () {
  // get token - in fast path you might cache tokens per VU
  let loginRes = http.post('http://localhost:8080/api/auth/login', JSON.stringify({username: 'alice', password: 'alice123'}), { headers: { 'Content-Type': 'application/json' }});
  let token = loginRes.json('data.token');
  const headers = { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' };

  // try borrow random book id (rotate)
  const bookId = Math.floor(Math.random() * 100) + 1;
  let res = http.post(`http://localhost:8080/api/borrow?userId=2&bookId=${bookId}`, null, { headers: headers });
  check(res, { 'status is 200': (r) => r.status === 200 || r.status === 201 });
  sleep(0.5);
}
```

运行：

```bash
k6 run test-scripts/k6/borrow-load.js
```

观察 p95 latency，错误率等。注意：并发借书会消耗库存，建议在测试前做数据准备或用只读搜索场景更安全。

# 六、安全 / 依赖扫描

目标：自动发现严重依赖漏洞（Snyk / OWASP Dependency Check），并在 PR 阶段阻止高危库进入主分支。

## Snyk（示例 CI 步骤）

在 GitHub Actions 中加入步骤（假设有 SNYK_TOKEN secret）：

```yaml
- name: Run Snyk
  uses: snyk/actions@master
  with:
    args: test
  env:
    SNYK_TOKEN: ${{ secrets.SNYK_TOKEN }}
```

## OWASP Dependency Check（maven plugin）

在 `pom.xml` 加插件，CI 执行：

```bash
mvn org.owasp:dependency-check-maven:check
```

# 八、CI（GitHub Actions）示例

文件：`.github/workflows/ci.yml`（主流水线：build -> unit tests -> integration tests -> sonar/snyk）

```yaml
name: CI

on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: root
          MYSQL_DATABASE: library_db
          MYSQL_USER: libuser
          MYSQL_PASSWORD: libpass
        ports:
          - 3306:3306
    steps:
      - uses: actions/checkout@v4
      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          java-version: '17'
      - name: Build (maven)
        run: mvn -U -B -DskipTests=false clean package
      - name: Run unit tests
        run: mvn test -DskipITs=true
      - name: Run integration tests (Testcontainers)
        run: mvn -DskipTests=false -DskipITs=false verify
      - name: JaCoCo report
        run: mvn jacoco:report
      - name: Snyk Scan
        uses: snyk/actions@master
        with:
          args: test
        env:
          SNYK_TOKEN: ${{ secrets.SNYK_TOKEN }}
```

> 说明：为了保证 Testcontainers 在 GitHub Actions 可用，通常不需要额外服务; Testcontainers 会拉镜像。如果你使用 docker-in-docker，配置稍微复杂。另一个策略是在 CI 里用 ephemeral docker-compose (services) as above or use hosted DB service.

## E2E 在 CI（单独 job）

```yaml
e2e:
  runs-on: ubuntu-latest
  needs: build
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-node@v4
      with: node-version: 18
    - run: npm ci
    - run: npm run build # frontend
    - run: docker-compose -f docker-compose.ci.yml up -d # start backend+db+redis
    - run: npx cypress run
```

# 十一、常见坑 & 排查建议

- Testcontainers 报错 `Cannot connect to Docker daemon`：CI runner / 本地没有 docker 或权限问题。解决：确保 Docker Desktop 在跑，或 CI 使用 runner with docker.
- Flyway 对 Testcontainers：要在测试启动前手动 migrate（见 IntegrationTestBase 示例）。
- 并发测试假阳性：记得清理 DB / 再次重复跑以排除残留数据影响。
- E2E flaky：尽量用 stable selectors、避免硬编码等待，使用 `cy.intercept` mock 外部请求减弱不确定性。
- k6 测试会修改 DB（借书），请在隔离环境或在测试结束后 reset 数据（可用 DB snapshot 或事务回滚策略）。
